## 1. ກ່ອນເລີ່ມ

**ການເປີດລະບົບ.** ປ້ອນທີ່ຢູ່ເຊີບເວີໃສ່ໂປຣແກຣມທ່ອງເວັບ. ລະບົບນີ້ເປັນໂມດູນໜຶ່ງທີ່ຢູ່ພາຍໃນ
ລະບົບໃຫຍ່ກວ່າ, ຈຶ່ງບໍ່ມີໜ້າເຂົ້າສູ່ລະບົບຂອງຕົນເອງ — ລະບົບແມ່ເປັນຜູ້ຢືນຢັນຕົວຕົນຜູ້ໃຊ້.

**ສາມຂໍ້ທີ່ຕ້ອງຮູ້ກ່ອນ:**

- ລະບົບເຮັດວຽກດ້ວຍ **ສີ່ສະກຸນເງິນ**: VNĐ, USD, THB, LAK. ທຸກເອກະສານມີສະກຸນເງິນຂອງຕົນ
  ແລະ ໜ້າຈໍຈະສະແດງສະກຸນເງິນນັ້ນສະເໝີ — ບໍ່ມີການແປງຄ່າແບບງຽບໆ.
- **ທຸກຈຳນວນເງິນມີແຫຼ່ງທີ່ມາ.** ຕົ້ນທຶນມາຈາກສູດຕົ້ນທຶນຂອງປະເພດລົດ; ລາຄາຂາຍມາຈາກ
  ໃບສະເໜີລາຄາທີ່ຕົກລົງກັບລູກຄ້າ. ບໍ່ມີບ່ອນໃດທີ່ພິມຕົວເລກລອຍໆໄດ້.
- **ລະບົບປະຕິເສດເລື້ອຍ ແລະ ບອກເຫດຜົນສະເໝີ.** ເມື່ອປຸ່ມຖືກສະກັດ ໃຫ້ອ່ານຂໍ້ຄວາມ — ມັນລະບຸ
  ສິ່ງທີ່ຂາດ ແລະ ໜ້າຈໍທີ່ຕ້ອງໄປແກ້. ພາກທີ 14 ລວບລວມຂໍ້ຄວາມທີ່ພົບເລື້ອຍທີ່ສຸດ.

## 2. ໂຄງໜ້າຈໍທີ່ໃຊ້ຮ່ວມກັນ

ສ່ວນນີ້ຄືກັນໝົດທຸກໜ້າຈໍ.

### 2.1. ແຖບເມນູດ້ານເທິງ

| ເມນູ (VI) | ເປີດໄປຫາ |
|---|---|
| **⌂ ມື້ນີ້** (Hôm nay) | ໜ້າຫຼັກ — ວຽກທີ່ຕ້ອງເຮັດມື້ນີ້ |
| **ການດຳເນີນງານ** (Vận hành) | ໃບສັ່ງປ່ອຍສິນຄ້າ · ຖ້ຽວລົດ · ການປ່ອຍລົດ · ການຕິດຕາມ · ການສຳເລັດ · ໃບລາຍການສິນຄ້າ |
| **ການຂາຍ** (Kinh doanh) | ລູກຄ້າ ແລະ ໂອກາດ · ໃບສະເໜີລາຄາຂົນສົ່ງ |
| **ຂໍ້ມູນຫຼັກ** (Dữ liệu gốc) | 10 ແຖບຂໍ້ມູນພື້ນຖານ |
| **ລາຍງານ ແລະ ອື່ນໆ** (Báo cáo và khác) | ວິເຄາະລາຍຮັບ-ຕົ້ນທຶນ · ຈຸດກວດ AI |

ກົດຊື່ກຸ່ມເພື່ອເປີດເມນູ ແລ້ວກົດເລືອກລາຍການ.

### 2.2. ປຸ່ມ ກັບຄືນ

ປຸ່ມ **ກັບຄືນ** (Quay lại) ຢູ່ **ດ້ານເທິງຂອງໜ້າ, ເບື້ອງຊ້າຍຂອງຊື່ໜ້າຈໍ**. ກົດເພື່ອກັບໄປໜ້າຈໍກ່ອນໜ້າ.

ມີສາມທາງທີ່ໃຫ້ຜົນຄືກັນ:

- ປຸ່ມ **← ກັບຄືນ** ເທິງໜ້າ
- ປຸ່ມ **Back** ຂອງໂປຣແກຣມທ່ອງເວັບ
- ການປັດກັບຄືນເທິງໂທລະສັບ, ຫຼື `Alt + ←`

ປຸ່ມຈະເຊື່ອງຕົວເອງຢູ່ໜ້າຈໍທຳອິດ — ບໍ່ມີບ່ອນໃຫ້ກັບໄປ ຈຶ່ງບໍ່ສະແດງປຸ່ມ.

> **ຂໍ້ແນະນຳ:** ທີ່ຢູ່ເທິງໂປຣແກຣມທ່ອງເວັບມີລະຫັດໜ້າຈໍຕິດຢູ່ (ຕົວຢ່າງ `#dispatch`).
> ການໂຫຼດຄືນ (F5) ຈະຢູ່ໜ້າຈໍເກົ່າ, ແລະ ລິ້ງທີ່ສົ່ງໃຫ້ເພື່ອນຮ່ວມງານຈະເປີດຕົງໜ້າຈໍທີ່ທ່ານເບິ່ງຢູ່.

### 2.3. ການປ່ຽນພາສາ

ປຸ່ມທຸງຊາດຢູ່ມຸມຂວາເທິງ: **ພາສາຫວຽດ · ພາສາອັງກິດ · ພາສາລາວ**. ລະບົບຈື່ການເລືອກໄວ້ໃຫ້ຄັ້ງຕໍ່ໄປ.

### 2.4. ກ່ອງຢືນຢັນ

ສິ່ງທີ່ຄືນຫຼັງບໍ່ໄດ້ — ການລຶບ, ການບັນທຶກເຂົ້າບັນຊີ, ການຍົກເລີກກະວຽກ — ຈະຖາມກ່ອນ ດ້ວຍກ່ອງ
ຂໍ້ຄວາມຂອງລະບົບເອງ. ກ່ອງນັ້ນບອກວ່າຈະເກີດຫຍັງຂຶ້ນ, ແລະ **ສອງປຸ່ມຂອງມັນເອີ້ນຊື່ການກະທຳຈິງ** —
ຕົວຢ່າງ `[ ເກັບໄວ້ ]` ແລະ `[ ລຶບລົດ ]`, ບໍ່ແມ່ນ ຕົກລົງ/ຍົກເລີກ. ກົດ `Esc` ຫຼື ກົດນອກກ່ອງເພື່ອຍົກເລີກ.

## 3. ຂັ້ນຕອນທັງໝົດ A → Z

```
 ໂອກາດ ──►  ໃບສະເໜີລາຄາ  ──►  ລູກຄ້າຕົກລົງ
                                     │
                                     ▼  (ອັດຕະໂນມັດ — ບໍ່ພິມດ້ວຍມື)
                              ໃບສັ່ງປ່ອຍສິນຄ້າ (DO)
                                     │
                                     ▼
                                ສ້າງຖ້ຽວລົດ (Trip)
                                     │
                                     ▼
                        ປ່ອຍລົດ: ກຳນົດລົດ ແລະ ຄົນຂັບ
                                     │
                                     ▼
                     ຄົນຂັບບັນທຶກແຕ່ລະຂັ້ນຕອນເທິງໂທລະສັບ
                                     │
                                     ▼
               ສຳເລັດການຈັດສົ່ງ: ຫຼັກຖານ POD + ລາຄາສຸດທ້າຍ
                                     │
                                     ▼
             ບັນທຶກເຂົ້າບັນຊີການຂາຍ → ໜີ້ຕ້ອງຮັບ
```

**ສາມຊັ້ນທີ່ຕ້ອງແຍກໃຫ້ຊັດ:**

| ຊັ້ນ | ແມ່ນຫຍັງ | ເປັນຂອງໃຜ |
|---|---|---|
| **ໃບສະເໜີລາຄາ (QT)** | ຂໍ້ຕົກລົງ: ເສັ້ນທາງໃດ, ປະເພດລົດໃດ, ລາຄາເທົ່າໃດ | ລູກຄ້າ ແລະ ລາຄາ |
| **ໃບສັ່ງປ່ອຍສິນຄ້າ (DO)** | ການຈັດສົ່ງໜຶ່ງຄັ້ງ: ສິນຄ້າຊຸດນີ້, ຮັບມື້ນີ້, ສົ່ງກ່ອນເວລານີ້ | ຄວາມຕ້ອງການຂອງລູກຄ້າ |
| **ຖ້ຽວລົດ (Trip)** | ການເຄື່ອນຍ້າຍຈິງ: ລົດຄັນໃດ, ຄົນຂັບຜູ້ໃດ, ອອກເວລາໃດ | ວິທີທີ່ບໍລິສັດປະຕິບັດ |

ໃບສະເໜີລາຄາໜຶ່ງໃບສ້າງໄດ້ຫຼາຍ DO. ຖ້ຽວໜຶ່ງອາດບັນທຸກຫຼາຍ DO, ແລະ DO ໜຶ່ງອາດຕ້ອງໃຊ້ຫຼາຍຖ້ຽວ.

> **ບໍ່ມີທາງສ້າງ DO ດ້ວຍມື.** DO ເກີດຂຶ້ນໄດ້ກໍເພາະລູກຄ້າຕົກລົງໃບສະເໜີລາຄາ — ນັ້ນຄືສິ່ງທີ່ໃຫ້
> ລາຄາທີ່ລັອກໄວ້. DO ທີ່ພິມດ້ວຍມືບໍ່ມີໃບສະເໜີລາຄາຢູ່ເບື້ອງຫຼັງ, ແລະ ຕອນສະສາງບັນຊີກໍບໍ່ມີຕົວເລກໃຫ້ອ້າງອີງ.

## 4. ຂໍ້ມູນຫຼັກ

**ໄປທີ່:** ຂໍ້ມູນຫຼັກ ເທິງແຖບເມນູ.

ໜ້ານີ້ມີ 10 ແຖບ. **ລຳດັບມີຄວາມສຳຄັນ** — ແຖບຫຼັງໆນຳໃຊ້ສິ່ງທີ່ແຖບກ່ອນໜ້າປະກາດໄວ້.

| ແຖບ | ປະກາດຫຍັງ | ຕ້ອງມີກ່ອນ |
|---|---|---|
| **0. ຕັ້ງຄ່າ A–Z** | ລຳດັບທີ່ແນະນຳ, ມີປຸ່ມກະໂດດໄປແຕ່ລະແຖບ | — |
| **1. ເສັ້ນທາງຂົນສົ່ງ** | ຊ່ວງ A → B → C, ໄລຍະທາງແຜນ, ຄ່າຜ່ານທາງ | — |

### 4.1. ເສັ້ນທາງ

**ການເພີ່ມເສັ້ນທາງ:** ປ້ອນລະຫັດເສັ້ນທາງ, ຊື່, ແລ້ວປ້ອນແຕ່ລະຊ່ວງ (ຕົ້ນທາງ → ປາຍທາງ, ກມ).

ເມື່ອບັນທຶກ ລະບົບຈະ **ຄົ້ນຫາພິກັດ** ຂອງແຕ່ລະຈຸດ ແລ້ວແຕ້ມເສັ້ນທາງຈິງ. ຖ້າຈຸດໃດຫາບໍ່ພົບ ຂໍ້ຄວາມ
ຈະບອກຊື່ຈຸດນັ້ນ — ໃຫ້ປ້ອນພິກັດດ້ວຍມື, ບໍ່ດັ່ງນັ້ນແຜນທີ່ຕິດຕາມຈະຂາດຈຸດ ແລະ ຕຳແໜ່ງລົດຈຳລອງຈະຜິດບ່ອນ.

> ເສັ້ນທາງຂ້າມຊາຍແດນຄວນປະກາດ **ຊ່ວງຕົວຈິງ**, ຕົວຢ່າງ
> `ວຽງຈັນ → ດ່ານນ້ຳພາວ → ທ່າເຮືອກົວໂລ`. ຖ້າປະກາດເປັນເສັ້ນຊື່ເສັ້ນດຽວ ແຜນທີ່ຈະແຕ້ມຜ່ານພູ
> ແລະ ຈຸດຢຸດຢູ່ດ່ານຈະບໍ່ປາກົດເລີຍ.

### 4.2. ສູດຕົ້ນທຶນ

ສູດມີ **ສອງຊັ້ນ**: ສູດມາດຕະຖານຕາມ **ປະເພດລົດ**, ແລະ ການປ່ຽນຄ່າສະເພາະລົດແຕ່ລະຄັນ ສຳລັບ
ຕົວເລກສອງສາມຕົວທີ່ຕ່າງກັນ.

ແຕ່ລະລາຍການມີ **Acc code** — ລະຫັດຈັດປະເພດຕົ້ນທຶນທີ່ພະແນກບັນຊີອອກໃຫ້. ຖ້າບໍ່ມີ, ຊຸດຂໍ້ມູນ
ສົ່ງມອບຈະລາຍງານວ່າລາຍການນັ້ນຍັງບໍ່ໄດ້ຈັດປະເພດ.

> **ສຳຄັນ:** ໃນຕາຕະລາງອົງປະກອບ, "ຄ່າຂົນສົ່ງ /ກກ" ແມ່ນ **ລາຄາຂາຍ**, ບໍ່ແມ່ນຕົ້ນທຶນ. ມີພຽງ
> ສີ່ອົງປະກອບອື່ນ (ນ້ຳມັນ, ເບ້ຍລ້ຽງຄົນຂັບ, ຄ່າຜ່ານທາງ, ຄ່າສາງ) ທີ່ປະກອບເປັນຕົ້ນທຶນ.
> ຢ່າບວກທັງຫ້າອົງປະກອບເຂົ້າເປັນຕົວເລກດຽວເດັດຂາດ.

### 4.3. ຄົນຂັບ ແລະ ໃບຂັບຂີ່

ຄົນຂັບທຸກຄົນຕ້ອງມີ **ຂໍ້ມູນບຸກຄົນ** (ຊື່, ປະເພດໃບຂັບຂີ່, ໜ້າທີ່) ແລະ **ໃບຂັບຂີ່** ທີ່ຍັງໃຊ້ໄດ້
ແລະ ປະເພດຂອງມັນຕ້ອງກົງກັບຂໍ້ມູນບຸກຄົນ.

**ໜ້າທີ່** ເປັນຕົວກຳນົດວ່າຜູ້ນັ້ນຂັບເປັນຄົນຂັບຫຼັກໄດ້ຫຼືບໍ່. ຜູ້ທີ່ບັນທຶກໄວ້ວ່າເປັນ "ຜູ້ຊ່ວຍຄົນຂັບ"
ຈະຖືກກຳນົດເປັນຄົນຂັບຫຼັກຕອນປ່ອຍລົດບໍ່ໄດ້.

**ກະວຽກ** (ແຖບ 4) ຕ້ອງຄອບຄຸມຊ່ວງເວລາຂອງຖ້ຽວ. ຖ້າບໍ່ມີກະວຽກ ການປ່ອຍລົດຈະຖືກສະກັດ.

## 5. ລູກຄ້າ ແລະ ໂອກາດ

**ໄປທີ່:** ການຂາຍ → ລູກຄ້າ ແລະ ໂອກາດ.

ນີ້ຄື **ບາດກ້າວທຳອິດຂອງຂັ້ນຕອນ**: ບັນທຶກສິ່ງທີ່ລູກຄ້າຕ້ອງການ ກ່ອນທີ່ຈະມີໃບສະເໜີລາຄາ.

### 5.1. ສາມມຸມມອງ

| ປຸ່ມ (VI) | ສະແດງຫຍັງ |
|---|---|
| **ກະດານໂອກາດ** (Bảng cơ hội) | Kanban — ລາກໂອກາດຂ້າມຂັ້ນຕອນ |
| **ລາຍຊື່** (Danh sách) | ຕາຕະລາງແບບແຖວ, ມີຕົວກັ່ນຕອງ ແລະ ການຄົ້ນຫາ |
| **ລູກຄ້າ** (Khách hàng) | ໂປຣໄຟລ໌ 360° ຕໍ່ລູກຄ້າ: ໂອກາດ, ໃບສະເໜີລາຄາ, DO, ລາຍຮັບ |

### 5.2. ປຸ່ມຕ່າງໆ

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **+ ໂອກາດ** (+ Cơ hội) | ສ້າງໂອກາດໃໝ່. ປ້ອນລູກຄ້າ (ຫຼື ຊື່ຜູ້ສົນໃຈທີ່ຍັງບໍ່ມີລະຫັດ), ຜູ້ຕິດຕໍ່, ແຫຼ່ງທີ່ມາ, ເສັ້ນທາງ, ປະເພດສິນຄ້າ, ນ້ຳໜັກ, ຈຳນວນຖ້ຽວຕໍ່ເດືອນ, ລາຄາທີ່ລູກຄ້າຄາດຫວັງ |

| **ເບິ່ງໃບສະເໜີລາຄາ** (Xem báo giá) | ເປີດໃບສະເໜີລາຄາທີ່ຜູກກັບໂອກາດນີ້ |

| **ເປີດຄືນ** (Mở lại) | ເອົາໂອກາດທີ່ປິດແລ້ວກັບມາເປັນໂອກາດທີ່ຍັງເຄື່ອນໄຫວ |

> ຕອນລູກຄ້າຕົກລົງ. ຢ່າລາກເຂົ້າສອງຂັ້ນນີ້ດ້ວຍມື.

## 6. ໃບສະເໜີລາຄາຂົນສົ່ງ

**ໄປທີ່:** ການຂາຍ → ໃບສະເໜີລາຄາຂົນສົ່ງ.

### 6.1. ແຖບເທິງ

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **+ ໃບສະເໜີລາຄາ** (+ Báo giá) | ເລີ່ມສ້າງໃບໃໝ່ |
| **↻ ໂຫຼດຄືນ** (Làm mới) | ໂຫຼດລາຍຊື່ຄືນ |

### 6.2. ພາຍໃນໃບສະເໜີລາຄາ

ແບບຟອມແບ່ງເປັນສາມແຖບ:

- **ລູກຄ້າ ແລະ ເສັ້ນທາງ** — ລູກຄ້າ, ເສັ້ນທາງ, ປະເພດລົດ, ຊ່ວງເວລາຮັບ/ສົ່ງ
- **ໃບສະເໜີລາຄາ ແລະ DO** — ສິນຄ້າ, ຕົ້ນທຶນ, ລາຄາ, ສ່ວນຫຼຸດ
- **ເອກະສານ ແລະ ໝາຍເຫດ** — ໄຟລ໌ແນບ, ໝາຍເຫດພາຍໃນ, ໝາຍເຫດເຖິງລູກຄ້າ

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **+ ເພີ່ມແຖວສິນຄ້າ** (+ Thêm dòng hàng hoá) | ລາຍການ, ຈຳນວນ, ຫົວໜ່ວຍ |
| **ບັນທຶກຮ່າງ** (Lưu nháp) | ບັນທຶກໄວ້; ບໍ່ມີການແຈ້ງໃຜ |
| **ສົ່ງອະນຸມັດພາຍໃນ** (Gửi duyệt nội bộ) | ໃຊ້ເມື່ອອັດຕາກຳໄລ **ຕ່ຳກວ່າເກນຂອງບໍລິສັດ** — ໃບສະເໜີລາຄາລໍຖ້າຫົວໜ້າ |
| **ອະນຸມັດ ແລະ ສົ່ງລູກຄ້າ** (Duyệt nội bộ và gửi khách) | ຫົວໜ້າອະນຸມັດ ແລະ ສົ່ງໃນຂັ້ນຕອນດຽວ |
| **ສົ່ງລູກຄ້າ** (Gửi khách) | ສົ່ງໃຫ້ລູກຄ້າ (ໃຊ້ໂດຍກົງເມື່ອກຳໄລຜ່ານເກນ) |
| **ລູກຄ້າປະຕິເສດ** (Khách từ chối) | ບັນທຶກການປະຕິເສດ; **ຕ້ອງລະບຸເຫດຜົນ** |
| **ເຮັດສຳເນົາ** (Nhân bản) | ສຳເນົາໃບນີ້ເປັນໃບໃໝ່ |
| **ປະຫວັດລາຄາ** (Lịch sử giá) | ທຸກຄັ້ງທີ່ແກ້ລາຄາຂອງໃບນີ້ |
| **ພິມພາຍໃນ** (In nội bộ) | ພິມແບບເຕັມ: ຕົ້ນທຶນແຕ່ລະລາຍການ, ກຳໄລ, ໝາຍເຫດພາຍໃນ |
| **☁ ເລືອກໄຟລ໌ ແລະ ແນບ** | ແນບໄຟລ໌ |

### 6.3. ລາຄາຖືກສ້າງຂຶ້ນແນວໃດ

1. ລະບົບອ່ານ **ສູດຕົ້ນທຶນ** ຂອງປະເພດລົດທີ່ເລືອກ ແລ້ວຄິດໄລ່ຕົ້ນທຶນຖ້ຽວ.
2. ທ່ານເລືອກ **ອັດຕາກຳໄລ** → ໄດ້ລາຄາຂາຍ.
3. **ສ່ວນຫຼຸດ** (ຖ້າມີ) ຄິດເປັນເປີເຊັນຫັກຈາກລາຄານັ້ນ.

ເລືອກສະກຸນເງິນໄດ້ຕໍ່ໃບ. ຖ້າເລືອກກີບລາວ ຕົ້ນທຶນຈະຖືກແປງຕາມອັດຕາທີ່ປະກາດໃນຂໍ້ມູນຫຼັກ.

> ໃບສະເໜີລາຄາທີ່ **ຕ່ຳກວ່າຕົ້ນທຶນ** ຈະຖືກປະຕິເສດຕອນກົດສົ່ງ.

### 6.4. ເມື່ອລູກຄ້າຕົກລົງ

ກົດປຸ່ມຢືນຢັນການຕົກລົງເທິງໃບສະເໜີລາຄາ. ໃນ **ທຸລະກຳດຽວ** ລະບົບຈະ:

- ຍ້າຍໃບສະເໜີລາຄາໄປສະຖານະ *ແຍກແລ້ວ*
- **ສ້າງ DO**, ພ້ອມເສັ້ນທາງ, ລາຄາທີ່ລັອກໄວ້ ແລະ ຊ່ວງເວລາ
- ຍ້າຍໂອກາດໄປຂັ້ນ *ຊະນະ*

ໃບສະເໜີລາຄາໜຶ່ງໃບສ້າງໄດ້ຫຼາຍ DO (ໜຶ່ງໃບຕໍ່ໜຶ່ງຊຸດສິນຄ້າ) — ລະບຸຈຳນວນຕອນຢືນຢັນ.

---

## 7. ໃບສັ່ງປ່ອຍສິນຄ້າ

**ໄປທີ່:** ການດຳເນີນງານ → ໃບສັ່ງປ່ອຍສິນຄ້າ (DO).

### 7.1. ຕົວນັບ

ຕົວນັບຫົກອັນທີ່ກົດໄດ້ ເພື່ອກັ່ນຕອງລາຍຊື່: **DO · ເສັ້ນທາງທີ່ອ້າງອີງ · ຕ້ອງດຳເນີນການ ·
ກຳລັງຂົນສົ່ງ · ສຳເລັດ · ຍົກເລີກ · ທັງໝົດ**.

### 7.2. ປຸ່ມຕ່າງໆ

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **DO ມາຈາກໃບສະເໜີລາຄາ →** | ພາໄປໜ້າໃບສະເໜີລາຄາ. ຢູ່ນີ້ **ບໍ່ມີ** ແບບຟອມ DO ເປົ່າ |
| **ສ້າງຖ້ຽວ** (Tạo chuyến) | ເລືອກ DO ໜຶ່ງໃບ ຫຼື ຫຼາຍໃບເທິງເສັ້ນທາງດຽວກັນ ແລ້ວສ້າງຖ້ຽວ |
| **ເບິ່ງໃບສະເໜີລາຄາ** | ເປີດໃບສະເໜີລາຄາຕົ້ນທາງຂອງ DO |
| **ເພີ່ມຄ່າໃຊ້ຈ່າຍ / ບັນທຶກຕົ້ນທຶນ** | ບັນທຶກຕົ້ນທຶນເພີ່ມເຕີມໃສ່ DO |

### 7.3. ການສ້າງຖ້ຽວ

ປ້ອນ: ລະຫັດຖ້ຽວ, ວັນ-ເວລາອອກເດີນທາງ, ຄວາມໄວແຜນ, ເວລາຈອດແຕ່ລະຊ່ວງ.

**ປະເພດຖ້ຽວ:**

| ປະເພດ (VI) | ໃຊ້ເມື່ອໃດ |
|---|---|
| **ຖ້ຽວດຽວ** (Một chiều) | ສົ່ງແລ້ວຈົບ |
| **ຫຼາຍຈຸດຈອດ** (Nhiều điểm giao) | ຖ້ຽວດຽວບັນທຸກຫຼາຍ DO, ແຕ່ລະໃບມີຈຸດສົ່ງຂອງຕົນ. ເຮັດໄດ້ສະເພາະເສັ້ນທາງທີ່ມີ **ສອງຊ່ວງຂຶ້ນໄປ** |
| **ໄປ-ກັບ (ມີຖ້ຽວກັບ)** (Khứ hồi) | ລວມການແລ່ນກັບເຂົ້າກອງລົດ. ຕ້ອງເລືອກ **ເສັ້ນທາງກັບ**, ແລະ ມັນຕ້ອງເລີ່ມຢູ່ບ່ອນທີ່ເສັ້ນທາງໄປສິ້ນສຸດ |

> **ການບັນທຸກສິນຄ້າໃນຖ້ຽວກັບຍັງບໍ່ຮອງຮັບຊົ່ວຄາວ.** DO ຂອງຖ້ຽວກັບຍັງເຊັນຮັບບໍ່ໄດ້, ຖ້ຽວຈຶ່ງ
> ຈະບໍ່ມີວັນປິດ ແລະ ລົດຈະຖືກຄ້າງໄວ້. ໃຫ້ເລືອກ *ກັບລົດເປົ່າ*, ຫຼື ສ້າງຖ້ຽວແຍກສຳລັບສິນຄ້າຂາກັບ.

## 8. ການປ່ອຍລົດ ແລະ ການປະຕິບັດ

**ໄປທີ່:** ການດຳເນີນງານ → ການປ່ອຍລົດ ແລະ ການປະຕິບັດ.

ນີ້ຄືບ່ອນທີ່ **ລົດ** ແລະ **ຄົນຂັບ** ຖືກກຳນົດໃຫ້ຖ້ຽວ.

### 8.1. ແຖບກັ່ນຕອງ

| ຕົວຄວບຄຸມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ຂອບເຂດ** | ກັ່ນຕອງຕາມກອງລົດ ແລະ ປະເພດລົດ |
| **ຄົ້ນຫາ** | ຫາລະຫັດ DO, ລູກຄ້າ ຫຼື ເສັ້ນທາງ |
| **‹ · ວັນທີ · ›** | ຖອຍ / ເລື່ອນໄປໜຶ່ງມື້ |
| **ມື້ນີ້** (Hôm nay) | ກັບມາວັນທີປັດຈຸບັນ |
| **⚡ ຈັດ DO ທີ່ເຫຼືອ** (Xếp DO còn lại) | ກຳນົດລົດອັດຕະໂນມັດໃຫ້ DO ທີ່ຍັງບໍ່ມີລົດ |

> **ໜ້ານີ້ກັ່ນຕອງຕາມ ວັນທີ.** ຖ້າຖັນ DO ຫວ່າງເປົ່າ ໃຫ້ອ່ານແຖວຂ້າງລຸ່ມ — ມັນບອກວ່າມີ DO ຈຳນວນ
> ເທົ່າໃດລໍຖ້າຢູ່ມື້ອື່ນ ແລະ ມີປຸ່ມກະໂດດໄປມື້ນັ້ນ. ປຸ່ມສີເຫຼືອງ **ຄ້າງເກົ່າ** ໝາຍເຖິງ DO ທີ່ມື້ຮັບສິນຄ້າ
> ຜ່ານໄປແລ້ວ ແຕ່ຍັງບໍ່ມີລົດ — ດ່ວນກວ່າວຽກຂອງມື້ອື່ນ.

### 8.2. ຕົວນັບ

**DO ມື້ນີ້ · ອອກເດີນທາງແລ້ວ · ລໍຖ້າກຳນົດລົດ · ຂາດຖ້ຽວ · ລົດຫວ່າງ/ທັງໝົດ · ຄົນຂັບເຂົ້າກະ**

### 8.3. ຖັນຊ້າຍ — DO ລໍຖ້າປ່ອຍລົດ

ຈັດກຸ່ມ **ຕາມເສັ້ນທາງ · ຕາມລູກຄ້າ · ຕາມກຳນົດສົ່ງ**. ຕິກຫຼາຍ DO ເພື່ອກຳນົດພ້ອມກັນ.

### 8.4. ຖັນກາງ — ກອງລົດແຕ່ລະສາຂາ

ແຕ່ລະກອງລົດສະແດງລົດ **ຫວ່າງ / ກຳລັງແລ່ນ / ຢູ່ອູ່ສ້ອມ**. ເມື່ອເລືອກ DO ຖັນນີ້ຈະກັ່ນຕອງເອົາ
ສະເພາະລົດທີ່ເໝາະສົມ.

ການຈັດລຳດັບ: **ເໝາະສົມທີ່ສຸດ · ກອງລົດດຽວກັນ · ຫວ່າງໄວທີ່ສຸດ**.

### 8.5. ປຸ່ມກຳນົດ

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ເລືອກລົດກ່ອນ** (Chọn xe trước) | ເລືອກລົດກ່ອນ ແລ້ວຈຶ່ງເລືອກ DO |
| **ປ່ຽນ** (Đổi) | ປ່ຽນລົດ ຫຼື ຄົນຂັບທີ່ກຳນົດໄວ້ |
| **ເພີ່ມ** (Thêm) | ເພີ່ມຜູ້ຊ່ວຍຄົນຂັບ |
| **ບັນທຶກການປ່ອຍລົດ** (Lưu điều phối) | ບັນທຶກໄວ້ ໂດຍຍັງບໍ່ປ່ອຍລົດອອກ |
| **ຢືນຢັນປ່ອຍລົດ ແລະ ອອກເດີນທາງ** (Chốt điều phối & xuất bến) | ຢືນຢັນ ແລະ ປ່ອຍລົດອອກ |

### 8.6. ຖັນຂວາ — ຂໍ້ຍົກເວັ້ນທີ່ຕ້ອງອະນຸມັດ

ສິ່ງທີ່ລະບົບສະກັດ ຫຼື ເຕືອນ: ເອກະສານລົດໃກ້ໝົດອາຍຸ, ໃບຂັບຂີ່ໃກ້ໝົດອາຍຸ, ປະເພດລົດຕ່າງຈາກໃບສະເໜີລາຄາ.
ກົດເພື່ອເບິ່ງລາຍລະອຽດ; ປຸ່ມ **← ກັບຄືນລາຍການຂໍ້ຍົກເວັ້ນ** ພາກັບມາ.

## 9. ການຕິດຕາມ ແລະ ຄວບຄຸມ

**ໄປທີ່:** ການດຳເນີນງານ → ການຕິດຕາມ ແລະ ຄວບຄຸມ.

ແຜນທີ່ ແລະ ຄວາມຄືບໜ້າຂອງຖ້ຽວທີ່ **ກຳລັງແລ່ນຢູ່**.

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ອັບເດດ GPS** (Cập nhật GPS) | ດຶງຕຳແໜ່ງຫຼ້າສຸດ |
| **ໂຫຼດຄືນ** (Tải lại) | ໂຫຼດລາຍຊື່ທັງໝົດຄືນ |
| **ອັບເດດເສັ້ນເວລາ** (Cập nhật timeline) | ໂຫຼດເສັ້ນເວລາຂອງແຕ່ລະຂັ້ນຕອນຄືນ |
| **+ ລາຍງານເຫດການໃໝ່** (+ Báo Sự Cố Mới) | ປ້ອນປະເພດ, ລະດັບຄວາມຮ້າຍແຮງ, ສະຖານທີ່, ຄຳອະທິບາຍ |
| **ສົ່ງລາຍງານເຫດການ** (Gửi báo cáo sự cố) | ບັນທຶກເຫດການ |

**ເທິງແຜນທີ່:**

- ເສັ້ນ **ສີແດງທຶບ** ຄືໄລຍະທີ່ແລ່ນໄປແລ້ວ, ເສັ້ນ **ຂີດສີເທົາ** ຄືໄລຍະທີ່ຍັງເຫຼືອ
- ໝຸດໝາຍຕຳແໜ່ງລົດ; ລົດທີ່ຢູ່ຈຸດດຽວກັນຈະຖືກແຍກອອກເລັກນ້ອຍເພື່ອບໍ່ໃຫ້ທັບກັນ
- ຈຸດຈອດມີໝຸດ ແລະ ເລກລຳດັບ

**ຕຳແໜ່ງຈຳລອງ.** ເມື່ອອຸປະກອນບໍ່ໄດ້ສົ່ງຂໍ້ມູນມາເກີນ 15 ນາທີ ລະບົບຈະປະມານຕຳແໜ່ງຈາກຄວາມຄືບໜ້າ
ຕາມເສັ້ນທາງ ແລະ ໝາຍໄວ້ຊັດເຈນວ່າເປັນ **ຕຳແໜ່ງຈຳລອງ**. ນັ້ນບໍ່ແມ່ນ GPS ຈິງ — ຂັ້ນຕອນທີ່ຄົນຂັບ
ບັນທຶກຕ່າງຫາກຄືຫຼັກຖານຈິງ.

## 10. ສຳເລັດການຈັດສົ່ງ

**ໄປທີ່:** ການດຳເນີນງານ → ການສຳເລັດການຈັດສົ່ງ.

ມີສອງແຖບ: **ລໍຖ້າສຳເລັດ** ແລະ **ສຳເລັດແລ້ວ**.

### 10.1. ແຖບ "ລໍຖ້າສຳເລັດ"

ແຕ່ລະແຖວຄື DO ໜຶ່ງໃບທີ່ລໍຖ້າການເຊັນຮັບ.

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ເບິ່ງ DO** | ລາຍລະອຽດ DO ແລະ ລາຄາ |
| **ສຳເລັດການຈັດສົ່ງ** (Hoàn tất giao hàng) | ເປີດແບບຟອມ POD |
| **↻** (ຂ້າງລາຄາ) | ໂຫຼດລາຄາຄືນ ຖ້າຊ່ອງນັ້ນຂຶ້ນວ່າ *ຍັງໂຫຼດລາຄາບໍ່ໄດ້* |

### 10.2. ແບບຟອມສຳເລັດການຈັດສົ່ງ

**ສ່ວນທີ 1 — ຫຼັກຖານການຈັດສົ່ງ (POD).** ໜຶ່ງບລັອກຕໍ່ໜຶ່ງຈຸດສົ່ງ:

- ເວລາສົ່ງ · ຜູ້ຮັບ · ເບີໂທ
- ຜົນ: *ສົ່ງຄົບ · ສົ່ງຂາດ · ລູກຄ້າປະຕິເສດ*
- **ຮູບໃບສົ່ງສິນຄ້າ** (ຈຳເປັນ)
- **ລາຍເຊັນຜູ້ຮັບ** — ເຊັນເທິງໜ້າຈໍໂດຍກົງ
- ສະພາບສິນຄ້າ / ໝາຍເຫດ

**ສ່ວນທີ 2 — ລາຄາສຸດທ້າຍ.** ລາຍການຕົ້ນທຶນຈາກສູດ, ແຕ່ລະລາຍການມີຊ່ອງ **ລູກຄ້າຈ່າຍເພີ່ມ**.
ຍອດລວມຈະໄຫຼໄປໃສ່ *ລາຄາສຸດທ້າຍ*.

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ເພີ່ມຄ່າໃຊ້ຈ່າຍ** (Thêm khoản phí) | ເພີ່ມແຖວຄ່າໃຊ້ຈ່າຍນອກຕາຕະລາງ |
| **ກັບຄືນ** (Quay lại) | ປິດໂດຍບໍ່ບັນທຶກ |
| **ສຳເລັດການຈັດສົ່ງ ແລະ ລັອກລາຄາ** (Hoàn tất giao hàng & chốt giá) | ສົ່ງຫຼັກຖານ, ລັອກລາຄາ, ປິດ DO |

> ຖ້ຽວແບບ **ຫຼາຍຈຸດຈອດ ຕ້ອງເຊັນຄົບທຸກຈຸດ** ຈຶ່ງຈະປິດ DO ໄດ້.

> ສຳລັບໃບສະເໜີລາຄາສະກຸນເງິນຕ່າງປະເທດທີ່ຍັງບໍ່ມີສູດຕົ້ນທຶນສະກຸນນັ້ນ, ຕາຕະລາງຈະຫຼຸດກັບໄປໃຊ້
> ສູດ VNĐ ແລະ **ບອກໄວ້ຊັດເຈນ**. ຊ່ອງເຫຼົ່ານັ້ນເປັນພຽງການອ້າງອີງ ແລະ ບໍ່ຖືກບວກເຂົ້າລາຄາຂາຍ.
> ຄ່າໃຊ້ຈ່າຍເພີ່ມຍັງປ້ອນໄດ້ຕາມປົກກະຕິ, ໃນສະກຸນເງິນຂອງໃບສະເໜີລາຄາເອງ.

### 10.3. ແຖບ "ສຳເລັດແລ້ວ"

ບັນທຶກຂອງ DO ທີ່ປິດແລ້ວ. ປຸ່ມ **ເບິ່ງບັນທຶກ** ເປີດ:

- ຫ້າຕົວເລກ: ລາຄາສະເໜີ · ລູກຄ້າຈ່າຍເພີ່ມ · ລາຄາສຸດທ້າຍ · ຕົ້ນທຶນພາຍໃນ · ກຳໄລ
- ລາຍລະອຽດ DO ຄົບຖ້ວນ
- **ບັນຊີລາຍຮັບ-ລາຍຈ່າຍ**: ທຸກລາຍການພ້ອມ **Acc code**, ແບ່ງເປັນຖັນ
  *ຕົກລົງເບື້ອງຕົ້ນ* / *ຕົວຈິງ* / *ລູກຄ້າຈ່າຍເພີ່ມ ຫຼື ສ່ວນຕ່າງ*
- ຮູບ ແລະ ລາຍເຊັນ POD

| ປຸ່ມ (VI) | ເຮັດຫຍັງ |
|---|---|
| **ອັບເດດຕົ້ນທຶນຕົວຈິງ / ລັອກຄ່າຂົນສົ່ງ** | ແກ້ຕົ້ນທຶນຕົວຈິງເມື່ອໃບບິນມາຮອດ |
| **ບັນທຶກເຂົ້າບັນຊີການຂາຍ** (Ghi sổ kinh doanh) | ສົ່ງໄປລະບົບໜີ້ຕ້ອງຮັບ — ເບິ່ງພາກທີ 11 |

## 11. ບັນທຶກເຂົ້າບັນຊີການຂາຍ

ປຸ່ມນີ້ຢູ່ເທິງ **ບັນທຶກທີ່ສຳເລັດແລ້ວ**, ຂ້າງປຸ່ມ *ອັບເດດຕົ້ນທຶນຕົວຈິງ / ລັອກຄ່າຂົນສົ່ງ*.

**ມັນເຮັດຫຍັງ:** ສົ່ງ DO ທີ່ສົ່ງສິນຄ້າແລ້ວ ໄປລະບົບບັນຊີ ເພື່ອສ້າງ **ໃບສັ່ງຂາຍ** ແລະ
**ບັນທຶກໜີ້ຕ້ອງຮັບ** ຕາມລາຄາສຸດທ້າຍທີ່ລັອກໄວ້.

**ວິທີໃຊ້:**

1. ກົດ **ບັນທຶກເຂົ້າບັນຊີການຂາຍ**
2. ອ່ານກ່ອງຢືນຢັນ ແລ້ວກົດ **ບັນທຶກ**
3. ເມື່ອສຳເລັດ ປຸ່ມຈະກາຍເປັນປ້າຍສີຂຽວ **ບັນທຶກເຂົ້າບັນຊີການຂາຍແລ້ວ · SO-…**

ເຄື່ອງໝາຍ *ສົ່ງມອບໃຫ້ບັນຊີ* ເທິງບັນທຶກ ຍັງສະແດງລະຫັດໃບສັ່ງຂາຍ ແລະ ຍອດໜີ້ເລີ່ມຕົ້ນນຳ.

> **ເຮັດໄດ້ຄັ້ງດຽວ.** ລະບົບບັນຊີບໍ່ເປີດໃຫ້ແກ້ ຫຼື ລຶບຈາກບ່ອນນີ້. ເມື່ອບັນທຶກແລ້ວ ປຸ່ມຈະຫາຍໄປ.

> ໜີ້ຖືກບັນທຶກໃນ **ສະກຸນເງິນຂອງໃບສະເໜີລາຄາເອງ** — DO ສະກຸນກີບລາວຈະລົງບັນຊີເປັນກີບ,
> ບໍ່ແປງເປັນດົງ.

ຖ້າຖືກປະຕິເສດ ປຸ່ມຈະຍັງຢູ່ ແລະ ມີແຖວສະແດງຂໍ້ຜິດພາດຫຼ້າສຸດ. ສາມກໍລະນີທີ່ພົບເລື້ອຍ:

| ຂໍ້ຜິດພາດ | ໝາຍຄວາມວ່າ | ໃຜແກ້ |
|---|---|---|
| ບໍ່ພົບລະຫັດລູກຄ້າໃນລະບົບບັນຊີ | ລູກຄ້ານັ້ນຍັງບໍ່ຖືກສ້າງຢູ່ຝ່າຍບັນຊີ | ທີມບັນຊີ |
| ຍັງບໍ່ໄດ້ເປີດໃຊ້ການເຊື່ອມຕໍ່ | ລະບົບບັນຊີຍັງບໍ່ຮັບຂໍ້ມູນ | ທີມບັນຊີ |
| ບໍ່ຮອງຮັບສະກຸນເງິນນີ້ | ລະບົບຮັບພຽງ VNĐ, USD, LAK | ຕົກລົງແນວທາງກັບຝ່າຍບັນຊີ |

## 12. ໜ້າສຳລັບຄົນຂັບ

ເປັນໜ້າແຍກຕ່າງຫາກສຳລັບຄົນຂັບ, ໃຊ້ເທິງ **ໂທລະສັບ**. ມັນເປັນແອັບອິດສະຫຼະ, ບໍ່ຢູ່ໃນລະບົບຫຼັກ.

**ວິທີເປີດ:** ແລ່ນ `python chay.py` ໃນໂຟນເດີ `EPL_TaiXe`, ແລ້ວເປີດທີ່ຢູ່ທີ່ມັນສະແດງອອກມາ
ເທິງໂທລະສັບທີ່ຢູ່ເຄືອຂ່າຍດຽວກັນ.

### 12.1. ລາຍການຖ້ຽວ

ກົດ **ຊື່ຂອງທ່ານ** ດ້ານເທິງເພື່ອເລືອກຕົວເອງ (ລະບົບຈື່ໄວ້ໃຫ້ຄັ້ງຕໍ່ໄປ). ລາຍການຈະສະແດງ
**ສະເພາະຖ້ຽວຂອງຄົນຂັບຜູ້ນັ້ນ**.

ແຕ່ລະບັດສະແດງ: ລະຫັດ DO · ລູກຄ້າ · ເສັ້ນທາງ · ສະຖານະ · ຊ່ວງທີ່ແລ່ນສຳເລັດ · ລົດ · ກຳນົດສົ່ງ.

### 12.2. ລາຍລະອຽດຖ້ຽວ

ກົດບັດເພື່ອເປີດ. ໜ້ານີ້ມີ:

- **ແຜນທີ່** — ໄລຍະທີ່ແລ່ນໄປແລ້ວເປັນສີແດງ, ສ່ວນທີ່ເຫຼືອເປັນເສັ້ນຂີດ, ມີໝຸດລົດ ແລະ ຈຸດຈອດ
- **ສີ່ຕົວເລກ**: ຄວາມຄືບໜ້າ % · ກມ ທີ່ເຫຼືອ · ຄວາມໄວ · ເວລາຄາດວ່າຈະຮອດ
- **ແຖບຂັ້ນຕອນ** ຫົກຂັ້ນ: ເຊັກອິນ → ຮັບສິນຄ້າ → ອອກເດີນທາງ → ມາຮອດ → ລົງສິນຄ້າ → ສົ່ງສຳເລັດ
- **ລາຍລະອຽດ DO** ແລະ **ລາຍການຊ່ວງທາງ**
- ປຸ່ມ **← ກັບຄືນ** ຢູ່ມຸມເທິງ

### 12.3. ສາມປຸ່ມປະຕິບັດ (ຕິດຢູ່ດ້ານລຸ່ມ)

| ປຸ່ມ | ເຮັດຫຍັງ |
|---|---|
| **📍 ບັນທຶກຂັ້ນຕອນ: …** | ບັນທຶກຂັ້ນຕອນຕໍ່ໄປຕາມລຳດັບ. ມັນເປັນ **ຂອງຈິງ** — ລົດຈະຂະຫຍັບເທິງແຜນທີ່ຂອງຜູ້ປ່ອຍລົດ. ຄືນຫຼັງບໍ່ໄດ້ |
| **✍ ສຳເລັດການຈັດສົ່ງ** | ເປີດແບບຟອມເຊັນຮັບ. **ໃຊ້ໄດ້ຫຼັງຈາກຂັ້ນ *ມາຮອດ* ເທົ່ານັ້ນ** |
| **⚠ ລາຍງານເຫດການ** | ປະເພດ, ລະດັບຄວາມຮ້າຍແຮງ, ສະຖານທີ່, ຄຳອະທິບາຍ — ຜູ້ປ່ອຍລົດເຫັນທັນທີ |

### 12.4. ການເຊັນຮັບເທິງໂທລະສັບ

ໜຶ່ງບລັອກຕໍ່ໜຶ່ງຈຸດສົ່ງ: ເວລາສົ່ງ · ຜູ້ຮັບ · ເບີໂທ · ຜົນ · **ຮູບໃບສົ່ງສິນຄ້າ** (ຖ່າຍດ້ວຍກ້ອງ) ·
**ລາຍເຊັນແຕ້ມດ້ວຍມື** · ໝາຍເຫດ. ມີຕາຕະລາງລາຄາໃຫ້ຄົນຂັບປ້ອນຈຳນວນທີ່ລູກຄ້າຈ່າຍເພີ່ມ.

> **ຂໍ້ຈຳກັດຂອງລຸ້ນສາທິດ:** ໜ້ານີ້ **ບໍ່ມີການເຂົ້າສູ່ລະບົບ**. ຄຳວ່າ "ຄົນຂັບແຕ່ລະຄົນເຫັນສະເພາະ
> ຖ້ຽວຂອງຕົນ" ເປັນພຽງການກັ່ນຕອງການສະແດງຜົນ, ບໍ່ແມ່ນຂອບເຂດຄວາມປອດໄພ — ຜູ້ໃດເປີດໜ້ານີ້
> ກໍເລືອກຊື່ຄົນອື່ນໄດ້.

## 13. ໜ້າຫຼັກ

### 13.1. ມື້ນີ້

- **ຕົວເລກຂອງມື້ນີ້**: DO · ຖ້ຽວທີ່ກຳລັງແລ່ນ · ໂອກາດທີ່ຕ້ອງໂທຫາ · ເຫດການ ·
  **ບັນທຶກທີ່ພ້ອມສົ່ງມອບ**
- **ຕ້ອງເອົາໃຈໃສ່ດຽວນີ້**: DO ເກີນກຳນົດ, ໃບສະເໜີລາຄາໃກ້ໝົດອາຍຸ, ເຫດການທີ່ຍັງບໍ່ປິດ
- **ຂັ້ນຕອນຂອງມື້ນີ້**: ຫົກສະຖານີຕໍ່ກັນ — ໂອກາດ → ໃບສະເໜີລາຄາ → DO → ປ່ອຍລົດ →
  ກຳລັງແລ່ນ → ສຳເລັດ. ສະຖານີສີເຫຼືອງຄືບ່ອນທີ່ວຽກກຳລັງກອງ
- **ຊັບພະຍາກອນມື້ນີ້**: ລົດຫວ່າງ / ກຳລັງແລ່ນ / ຢູ່ອູ່ສ້ອມ, ຄົນຂັບຫວ່າງ, ແລະ **ສອງຄຳເຕືອນ
  ເລື່ອງເອກະສານ** — ລົດທີ່ໃກ້ໝົດອາຍຸກວດສະພາບ ແລະ ຄົນຂັບທີ່ໃບຂັບຂີ່ໃກ້ໝົດອາຍຸ

> ສອງຄຳເຕືອນນັ້ນນັບຢ່າງຖືກຕ້ອງວ່າ **ຈະສະກັດການປ່ອຍລົດ** ແມ່ນຫຍັງແດ່, ລວມທັງບັນທຶກທີ່ຍັງ
> ບໍ່ເຄີຍປ້ອນວັນທີເລີຍ. ຖ້າມາຮູ້ຕອນກຳນົດລົດ ກໍຊ້າໄປແລ້ວ.

### 13.2. ໜ້າສະຫຼຸບ (Dashboard)

ຕົວເລກລວມ ແລະ ແຜນຜັງຂັ້ນຕອນ A–Z ຂອງແປດກຸ່ມໜ້າທີ່.

### 13.3. ວິເຄາະລາຍຮັບ-ຕົ້ນທຶນ

**ໄປທີ່:** ລາຍງານ ແລະ ອື່ນໆ → ວິເຄາະລາຍຮັບ-ຕົ້ນທຶນ. ຕົ້ນທຶນ, ລາຄາສະເໜີ ແລະ ກຳໄລ
ຕາມເສັ້ນທາງ, ຕາມລົດ ແລະ ຕາມລູກຄ້າ.

## 14. ຂໍ້ຄວາມປະຕິເສດທີ່ພົບເລື້ອຍ

ລະບົບຈະສະກັດຢູ່ບ່ອນທີ່ມີຄວາມສ່ຽງຈິງ. ຕາຕະລາງນີ້ອະທິບາຍຂໍ້ຄວາມທີ່ພົບເລື້ອຍທີ່ສຸດ.

| ລະບົບບອກວ່າ | ໝາຍຄວາມວ່າ | ໄປແກ້ຢູ່ໃສ |
|---|---|---|
| ປະເພດລົດບໍ່ກົງກັບໃບສະເໜີລາຄາ | ລົດທີ່ເລືອກຕ່າງຈາກປະເພດທີ່ຄິດລາຄາໃຫ້ລູກຄ້າ | ເລືອກປະເພດໃຫ້ຖືກ ຫຼື ແກ້ໃບສະເໜີລາຄາ |
| ເອກະສານລົດຂາດ ຫຼື ໝົດອາຍຸ | ກວດສະພາບ / ປະກັນໄພ / ບຳລຸງຮັກສາ ໝົດອາຍຸ **ຫຼື ຍັງບໍ່ເຄີຍປ້ອນ** | ຂໍ້ມູນຫຼັກ → ພາຫະນະ |
| ໃບຂັບຂີ່ບໍ່ເໝາະສົມ ຫຼື ໝົດອາຍຸ | ບໍ່ມີ, ໝົດອາຍຸ, ຫຼື ປະເພດຕ່າງຈາກຂໍ້ມູນບຸກຄົນ | ຂໍ້ມູນຫຼັກ → ຄົນຂັບ ແລະ ໃບຂັບຂີ່ |
| ບໍ່ມີກະວຽກຄອບຄຸມເວລານີ້ | ຄົນຂັບບໍ່ມີກະວຽກໃນຊ່ວງເວລາຂອງຖ້ຽວ | ຂໍ້ມູນຫຼັກ → ຈັດຕາຕະລາງລົດ ແລະ ຄົນຂັບ |
| ຜູ້ທີ່ເລືອກບໍ່ແມ່ນຄົນຂັບຫຼັກ | ບັນທຶກໄວ້ວ່າເປັນຜູ້ຊ່ວຍຄົນຂັບ | ເລືອກຜູ້ອື່ນ ຫຼື ປ່ຽນໜ້າທີ່ |
| ລົດ/ຄົນຂັບບໍ່ຫວ່າງ | ຍັງຄ້າງຖ້ຽວທີ່ບໍ່ທັນປິດ | ປິດຖ້ຽວນັ້ນ, ຢືນຢັນການກັບເຂົ້າກອງລົດ, ຫຼື ຍົກເລີກຖ້ຽວ |
| ນ້ຳໜັກ / ປະລິມາດເກີນ | ສິນຄ້າທີ່ແຈ້ງເກີນຄວາມສາມາດບັນທຸກ | ເລືອກລົດໃຫຍ່ກວ່າ ຫຼື ແບ່ງສິນຄ້າ |
| ການກຳນົດຢູ່ນອກຊ່ວງເວລາ | ເວລາກຳນົດຕົກນອກຊ່ວງຮັບ/ສົ່ງຂອງ DO | ແກ້ຊ່ວງເວລາເທິງ DO ກ່ອນ |
| ຕ້ອງມີ POD ຄົບທຸກຊ່ວງສົ່ງ | ຖ້ຽວຫຼາຍຈຸດຈອດຍັງມີຈຸດທີ່ບໍ່ທັນເຊັນ | ເຊັນຈຸດທີ່ຍັງເຫຼືອ |
| ສະສາງໄດ້ຫຼັງຖ້ຽວປິດແລ້ວເທົ່ານັ້ນ | ຖ້ຽວໄປ-ກັບ ຍັງບໍ່ໄດ້ຢືນຢັນການກັບເຂົ້າກອງລົດ | ຢືນຢັນການກັບກ່ອນ |
| ໃບສະເໜີລາຄາຕ່ຳກວ່າຕົ້ນທຶນ | ລາຄາຂາຍຕ່ຳກວ່າຕົ້ນທຶນ | ແກ້ລາຄາ ຫຼື ອັດຕາກຳໄລ |
| ບໍ່ມີສູດຕົ້ນທຶນສຳລັບປະເພດລົດນີ້ | ປະເພດນີ້ຍັງບໍ່ມີສູດ | ຂໍ້ມູນຫຼັກ → ສູດຕົ້ນທຶນ |

**ຫຼັກການທົ່ວໄປເມື່ອຖືກສະກັດ:** ອ່ານຂໍ້ຄວາມ, ໄປເຮັດສິ່ງດຽວທີ່ມັນລະບຸ, ແລ້ວກົດໃໝ່.
ລະບົບຈະບອກສະເໝີວ່າແມ່ນບັນທຶກໃດ ແລະ ຕ້ອງໄປໜ້າຈໍໃດ.

## 15. ພົດຈະນານຸກົມຄຳສັບ

| ຄຳສັບ | ຄວາມໝາຍ |
|---|---|
| **ໂອກາດ** (Cơ hội) | ຄວາມຕ້ອງການຂອງລູກຄ້າ, ບັນທຶກໄວ້ກ່ອນມີໃບສະເໜີລາຄາ |
| **ໃບສະເໜີລາຄາ (QT)** | ລາຄາທີ່ຕົກລົງກັນສຳລັບເສັ້ນທາງ ແລະ ປະເພດລົດໜຶ່ງ |
| **ໃບສັ່ງປ່ອຍສິນຄ້າ (DO)** | ການຈັດສົ່ງໜຶ່ງຄັ້ງ, ສ້າງຈາກໃບສະເໜີລາຄາທີ່ລູກຄ້າຕົກລົງ |
| **ຖ້ຽວ (Trip)** | ການເຄື່ອນຍ້າຍຈິງ: ລົດ, ຄົນຂັບ, ເວລາອອກເດີນທາງ |
| **ຊ່ວງທາງ (Leg)** | ສ່ວນໜຶ່ງຂອງຖ້ຽວ, ຈາກຈຸດໜຶ່ງໄປອີກຈຸດໜຶ່ງ |
| **POD** | ຫຼັກຖານການຈັດສົ່ງ: ຮູບໃບສົ່ງສິນຄ້າ ແລະ ລາຍເຊັນຜູ້ຮັບ |
| **ຂັ້ນຕອນ (Mốc)** | ຫົກຂັ້ນ: ເຊັກອິນ, ຮັບສິນຄ້າ, ອອກເດີນທາງ, ມາຮອດ, ລົງສິນຄ້າ, ສົ່ງສຳເລັດ |
| **ຕົ້ນທຶນ** | ຈຳນວນທີ່ບໍລິສັດຕ້ອງຈ່າຍສຳລັບຖ້ຽວນັ້ນ |
| **ຄ່າຂົນສົ່ງ** | ຈຳນວນທີ່ລູກຄ້າຈ່າຍ |
| **ອັດຕາກຳໄລ** | ສ່ວນຕ່າງລະຫວ່າງລາຄາຂາຍ ແລະ ຕົ້ນທຶນ, ຄິດເປັນເປີເຊັນ |
| **Acc code** | ລະຫັດຈັດປະເພດຕົ້ນທຶນ, ພະແນກບັນຊີເປັນຜູ້ອອກໃຫ້ |
| **ຊຸດຂໍ້ມູນສົ່ງມອບ** | ຂໍ້ມູນຄົບຖ້ວນຂອງ DO ທີ່ປິດແລ້ວ, ໃຫ້ຝ່າຍບັນຊີອອກເອກະສານ |
| **ບັນທຶກເຂົ້າບັນຊີການຂາຍ** | ສົ່ງ DO ທີ່ສົ່ງສິນຄ້າແລ້ວໄປໃຫ້ບັນຊີສ້າງໃບສັ່ງຂາຍ |
| **ກັບລົດເປົ່າ** | ຊ່ວງແລ່ນກັບເຂົ້າກອງລົດ ໂດຍບໍ່ບັນທຸກສິນຄ້າ |
| **ຄ້າງເກົ່າ (Backlog)** | DO ທີ່ມື້ຮັບສິນຄ້າຜ່ານໄປແລ້ວ ແຕ່ຍັງບໍ່ມີລົດ |
